# 验收记录

日期：2026-10-20。环境：Windows 浏览器，经受信任 SSH 中转到 macOS arm64；Mac 原 App 所带 CLI 为 `0.163.0-alpha.10.2`，Bun 为 1.4.0。

## 已取得的证据

- Mac、SSH 中转服务器、Windows 三处回环状态接口均返回原桌面 IPC 已连接。
- 独立测试会话中的既有历史可在网页读取。
- 从 Windows 网页提交测试文本后，同一会话返回 `ARGUS_WEB_ROUNDTRIP_OK_20261020`；原桌面 App 的会话所有者执行，读取进程没有启动回合。
- 根据用户明确要求，通过窗口转发补全并发送了指定项目下的原生未发送草稿；原 App 创建会话并显示开始执行。私人任务正文和画面没有纳入本仓库。
- 指定项目内的新建草稿在首次发送时创建会话，由原 App 接管；目录中的项目与工作目录一致，收到 `ARGUS_PROJECT_CHAT_OK_20261020`。同一创建编号再次提交返回同一会话。
- 网页“停止”使隔离测试回合变为 `interrupted`；修正此版本所需的追加上下文后，同一运行回合接收追加指令并返回 `ARGUS_WEB_STEER_OK_20261020`。
- 相同消息编号多次提交返回同一回合，历史中该用户消息只有一条；同编号改内容返回 409。真实服务拒绝陌生 Host、跨域 Origin 和缺 token 的写请求，均为 403。
- 更新桥接服务后网页自动恢复 WebSocket；有意终止本工具自己的 Windows SSH 子进程后，监督进程替换连接，网页恢复可发送。未发送草稿在桥接重启、刷新网页与隧道重连后保持。
- 包测试覆盖中文帧分片、超大帧拒绝、canonical history、补丁路径、增量正文、项目旧 ID 映射、持久消息编号、重启后的未知状态与创建编号，以及 Host/Origin/token 检查。

## 验证边界

完整测试的命令、退出状态、数量与安装摘要记录在发布说明及本地 `verification.json` 中。命令/文件审批适配没有触发真实审批验证；附件、浏览器、原生未发送草稿镜像和复杂交互由窗口组件处理。不能把这次隔离验收等同于长期在线或所有 App 版本兼容保证。

初始 Windows 全套运行遇到已有 Unix 路径和 shell 假设。将 Windows CRLF 文件归档到 Mac 后，shell 静态/运行测试也会失败；规范化临时副本后只剩一项从 `/tmp` 启动触发的持久路径保护。最终发布以 Git 归档、Mac 持久目录中的完整套件为依据，不把这些早期环境结果描述为全绿。

## 复验

在 Mac 的持久项目目录中解开发布 Git 归档，运行 `bun install --frozen-lockfile`、`bun test`、`bun run typecheck`、`bun run desktop:build`。从 Windows 生成归档时使用 `git -c core.autocrlf=false archive`，并比对归档 SHA256；只用默认 `git archive` 仍可能受到 Windows 自动换行配置影响。随后用独立测试会话检查发送、停止、追加指令、重复编号与桥接重启恢复。不要用用户正在执行的任务测试停止。

检查 `/api/status` 的 Git 提交与源码摘要，再分别检查中转服务器和 Windows 的相同状态。仅凭配置文件或排队回执不能证明 Mac 原 App 已执行。
