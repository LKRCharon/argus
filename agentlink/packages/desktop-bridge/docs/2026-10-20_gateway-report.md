# Argus 多设备网关验证报告

日期：2026-10-20。范围见 [security-scope.md](security-scope.md)。目标是在保留原桌面会话的前提下，经密码保护的入口控制所有者的 Mac 和 Windows。此次检查使用 Bun、TypeScript、Windows OpenSSH、原生 Codex IPC、Linux Nginx 和浏览器；没有引入模型代审批。

## 发现与处理

| 编号 | 级别 / 状态 / 置信度 | 证据 | 位置 | 结论与处理 |
| --- | --- | --- | --- | --- |
| F-001 | 中 / 已验证并修复 / 高 | E-001、E-004 | `src/gateway.ts`、`gateway-auth.ts` | 本地回环桥接不能直接暴露公网。新增统一鉴权层，覆盖页面、API 和 WS；复用 OJ 校验值并限制账号白名单，认证 Cookie 不转发到设备 |
| F-002 | 信息 / 已验证并修复 / 高 | E-001、E-005 | `src/bridge.ts`、`delivery.ts`、`web/app.ts` | 每次流式补丁重复扫描并查询历史投递。改为原生顺序应用、40 ms 最大合并间隔、内存投递索引和动画帧渲染；保留版本连续性及持久投递语义 |
| F-003 | 信息 / 已验证并实现 / 高 | E-001、E-003 | `src/ipc.ts`、`platform.ts`、`deploy/install-windows.ts` | 受控主机此前仅支持 Mac。新增 Windows 命名管道、原生 CLI 发现、深链打开、独立安装版本、后台监督及登录启动 |
| F-004 | 低 / 已验证并缓解 / 高 | E-001 | `src/gateway.ts` | Bun 1.3.14 服务主动关闭 WS 后可能残留连接计数，最小独立程序可复现。连接与监听先关闭，对原生排空 Promise 设置上限，使服务重启能结束 |

F-001 表示设计边界：未鉴权的回环桥接保留在回环地址，没有把旧服务当作已存在的公网漏洞。随机路径提供额外隐藏层；HTTPS 和 SSH 提供传输加密，受信任网关仍可见数据。

## 请求路径

P-001，类型 `callflow`：浏览器先请求登录页（E-004），网关核对允许的 OJ 账号及 PBKDF2 校验值（E-001、F-001），成功后发安全 Cookie 和随机路径。后续请求需该会话有效，网关只代理配置中的回环设备。修改请求继续验证原生 token 和 Origin；WS 同样检查登录和 Origin，再按顺序转发。原 App 会话所有者执行指令，目录读取进程不抢占 writer（E-003、F-003）。退出或失效撤销 HTTP/WS 权限（E-001、F-001）。

## 时间与边界

先确认 Windows 命名管道和原生项目读取，再完成网关及性能修正；随后运行隔离往返、Mac 完整套件和 Linux 网关测试，最后发布 HTTPS 入口并检查生产鉴权、OJ 文件完整性和原 App 进程保留。详细提交、时间、命令退出码和源码摘要存放在私有交付记录，通用代码及本报告可公开。

性能数值来自合成突发数据，不能当作日常操作或模型推理提速比例。未完成长期在线测试、真实文件审批、附件、原生草稿和全部复杂交互验证。桌面 follower 协议随 App 版本变化，升级需复验；当前已有回合的沙箱不能原地替换，后续发送使用完全访问。
